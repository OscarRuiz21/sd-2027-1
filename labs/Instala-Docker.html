Tu sistema

Antes de empezar: elige tu sistema arriba

Los comandos y los instaladores cambian según el sistema y según el procesador. Toda la guía se adapta a lo que elijas.

1 · Qué vas a instalar y por qué

Docker corre contenedores: programas empaquetados con todo lo que necesitan para ejecutarse, aislados del resto de tu máquina. En este curso son la herramienta central: un sistema distribuido son varios servicios corriendo y hablándose entre sí, y con Docker vas a levantar todos esos servicios en tu propia computadora, desde la primera sesión de laboratorio.

En Windows se instala Docker Desktop: la aplicación completa, con el motor y una interfaz gráfica para ver qué está corriendo.

En macOS se instala Docker Desktop: la aplicación completa, con el motor y una interfaz gráfica para ver qué está corriendo.

En Linux se instala Docker Engine: el motor solo, sin interfaz gráfica. Es más ligero que el Docker Desktop de Windows y Mac, y todo lo que hagamos en el curso es por terminal de todas formas.

Docker Desktop y Docker Engine son gratis para uso personal y educativo. No necesitas crear ninguna cuenta para instalarlos ni para usarlos en el curso.

2 · ¿Qué procesador tiene tu máquina?

Hay dos familias de procesador y el instalador es distinto para cada una. Treinta segundos para averiguar la tuya:

Abre Configuración → Sistema → Acerca de y busca "Tipo de sistema":

  • "Procesador x64": eres x64. Es la enorme mayoría de las laptops con Windows.
  • "Procesador basado en ARM": eres ARM64 (algunas Surface y laptops con Snapdragon).

Menú manzana → Acerca de esta Mac:

  • Dice "Chip Apple M1" (o M2, M3, M4): eres Apple Silicon.
  • Dice "Intel": eres Intel.

En tu terminal:

uname -m

Si imprime x86_64 eres x64; si imprime aarch64 eres ARM64. Los comandos de abajo funcionan igual en las dos, así que aquí solo lo confirmas.

3 · Requisitos

  • Windows 10 (22H2) o Windows 11 (23H2 o más nuevo), de 64 bits. La edición Home sirve perfectamente: solo corre contenedores Linux, que es lo único que usamos en el curso.
  • 8 GB de RAM recomendados (con 4 se puede, pero vas a sentir la máquina lenta con varios servicios arriba).
  • Virtualización habilitada en el BIOS/UEFI. En casi todas las laptops ya viene activada; si no, en la tabla de errores está el arreglo.
  • WSL 2, el subsistema de Linux de Windows. Lo instalamos en el paso siguiente.
  • Una de las últimas tres versiones mayores de macOS. Si tu Mac se actualiza normal, estás dentro.
  • 4 GB de RAM mínimo; 8 recomendados.
  • Una distribución de 64 bits razonablemente actual. Probé esta guía tal cual, comando por comando, en Ubuntu 24.04, Debian 13 y Fedora 44; el mismo script cubre también Ubuntu 22.04+, Debian 12 y derivados. Para Arch hay bloque aparte abajo.
  • Poder usar sudo.

4 · Instalación

4.1 · Primero WSL 2

Docker en Windows corre los contenedores dentro de un Linux ligero que administra el propio Windows: eso es WSL 2. Abre PowerShell como administrador (menú Inicio → escribe "PowerShell" → clic derecho → "Ejecutar como administrador") y corre:

wsl --install

Si te dice que ya está instalado, actualízalo:

wsl --update

Si te pide reiniciar, reinicia antes de seguir.

4.2 · Ahora Docker Desktop

En la misma PowerShell (ya no necesita ser de administrador):

winget install Docker.DockerDesktop

O si prefieres el instalador clásico de doble clic: descarga Docker Desktop para x64 (o el de ARM64 si tu "Tipo de sistema" dice ARM) y córrelo con las opciones que trae por defecto. Deja marcada la opción de WSL 2 si te la pregunta.

Al terminar, cierra tu sesión de Windows y vuelve a entrar (el instalador te agrega a un grupo de usuarios y eso se aplica al reingresar).

4.3 · Ábrelo una vez

Abre Docker Desktop desde el menú Inicio. La primera vez te muestra el acuerdo de servicio (acéptalo, el uso educativo entra en la capa gratuita) y te ofrece iniciar sesión: dale "Skip", no necesitas cuenta. Espera a que abajo a la izquierda la ballena se ponga verde con el estado "Engine running". Puede tardar un par de minutos la primera vez.

4.1 · Instala Docker Desktop

Si tienes Homebrew, es una línea:

brew install --cask docker-desktop

Sin Homebrew: descarga el DMG de tu procesador, Apple Silicon (M1 a M4) o Intel, ábrelo y arrastra Docker a la carpeta Aplicaciones, como cualquier app.

4.2 · Ábrelo una vez

Abre Docker desde Aplicaciones. La primera vez te muestra el acuerdo de servicio (acéptalo, el uso educativo entra en la capa gratuita), te pide tu contraseña de la Mac para instalar su componente de red, y te ofrece iniciar sesión: dale "Skip", no necesitas cuenta. Cuando la ballena aparezca fija en la barra de menús, el motor ya está corriendo.

4.1 · El script oficial (Ubuntu, Debian, Fedora y derivados)

Docker mantiene un script que detecta tu distribución, da de alta su repositorio oficial e instala el motor completo con el plugin de Compose:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

Tarda unos minutos. Al final imprime la versión instalada del cliente y el servidor.

4.2 · Úsalo sin sudo y déjalo encendido

# tu usuario entra al grupo docker
sudo usermod -aG docker $USER

# que el motor arranque solo al prender la máquina
sudo systemctl enable --now docker

El grupo se aplica al cerrar sesión y volver a entrar. Si quieres probar ya, sin salirte, corre newgrp docker en la terminal y esa terminal ya lo trae aplicado.

4.3 · Si usas Arch

sudo pacman -S docker docker-compose
sudo usermod -aG docker $USER
sudo systemctl enable --now docker.service

Y el mismo cierre de sesión para que aplique el grupo.

Deberías ver algo asíDocker version 29.4.0, build 9d7ad9f Docker Compose version v5.1.2 Hello from Docker! This message shows that your installation appears to be working correctly. ...

Los números pueden variar; lo que importa es el "Hello from Docker!". Ese mensajito hizo el viaje completo: tu terminal le pidió al motor un contenedor, el motor bajó la imagen de internet, la corrió y te trajo la salida. Es exactamente el ciclo que vamos a usar todo el semestre.

Los errores de siempre

Lo que pasaQué significa y qué haces
Windows: "WSL 2 installation is incomplete" o pide un kernel más nuevoPowerShell como administrador → wsl --update → reinicia Docker Desktop.
Windows: "Virtualization support not detected" o "hardware assisted virtualization... not enabled"La virtualización está apagada en el BIOS/UEFI. Se enciende ahí: busca Intel VT-x o AMD SVM y actívalo. Si no sabes entrar a tu BIOS, mándame modelo de tu laptop y te paso los pasos.
Windows: "you are not allowed to use Docker, you must be in the 'docker-users' group"Te faltó cerrar la sesión de Windows después de instalar. Cierra sesión, vuelve a entrar y abre Docker Desktop de nuevo.
Linux: permission denied ... docker.sockTe faltó el usermod -aG docker $USER, o no has cerrado sesión desde que lo corriste. El grupo se aplica al volver a entrar; newgrp docker lo aplica en la terminal actual.
Linux: Cannot connect to the Docker daemonEl motor está apagado: sudo systemctl start docker. Con el enable --now del paso 4.2 no vuelve a pasar.
Mac y Windows: docker: command not found con todo instaladoLa aplicación Docker Desktop tiene que estar abierta: el comando funciona mientras la app corre. Ábrela y prueba en una terminal nueva.
Te pide iniciar sesión o crear cuentaNo es necesaria para nada del curso. Dale "Skip" o cierra el aviso.
La descarga de hello-world se queda colgadaCasi siempre es la red (los datos del celular a veces bloquean estos puertos). Prueba en otra red y avísame si sigue.
