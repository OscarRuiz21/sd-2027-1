Parte 0 · Qué es Docker y qué piezas tiene

Un contenedor es un proceso empaquetado con todo lo que necesita para correr (sistema base, librerías, configuración) y aislado del resto de tu máquina. No es una máquina virtual: no trae su propio kernel ni "arranca un sistema"; es un proceso de tu máquina con una burbuja alrededor, y por eso levanta en milisegundos.

Para qué lo queremos aquí: un sistema distribuido son varios servicios corriendo a la vez, y este curso los vas a levantar todos en tu computadora, idénticos a los del profesor y a los de tus 39 compañeros. La frase "en mi máquina sí funciona" se muere hoy: si corre en un contenedor, corre igual en todas partes.

PiezaQué es
ImagenLa plantilla, de solo lectura: sistema base + librerías + tu aplicación, congelados en capas.
ContenedorUna instancia en ejecución de esa imagen. De una imagen puedes lanzar muchos, como de una clase creas muchos objetos.
DockerfileLa receta de texto con la que se construye una imagen. Hoy escribes tu primera.
Docker HubLa tienda pública de imágenes: de ahí salen nginx, postgres, alpine…
Engine + CLIEl motor que corre los contenedores y el comando docker con el que le hablas.
imagen (plantilla, solo lectura) │ docker run ├──► contenedor 1 (en ejecución) ├──► contenedor 2 └──► contenedor 3

Ejercicio 1 · Una imagen, muchos contenedores

Baja una imagen de la tienda y lanza dos contenedores desde la misma plantilla:

docker pull nginx:alpine
docker images
docker run -d --name web1 nginx:alpine
docker run -d --name web2 nginx:alpine
docker ps
Deberías ver algo así (tus IDs cambian)NAMES IMAGE STATUS web2 nginx:alpine Up 3 seconds web1 nginx:alpine Up 5 seconds

Dos contenedores vivos, misma imagen. Cada uno tiene su propio sistema de archivos y sus propios procesos aunque compartan plantilla: imagen es a contenedor lo que clase es a objeto.

Ejercicio 2 · El ciclo de vida

created ──► running ──► stopped ──► removed (start) (stop) (rm)
docker stop web1
docker ps          # web1 ya no aparece…
docker ps -a       # …pero aquí sí: "Exited (0)"
docker start web1  # y revive

Detener no es borrar. docker ps enseña solo lo que corre; docker ps -a enseña todo, incluidos los detenidos. Borrar de verdad es docker rm (con el contenedor detenido).

Ejercicio 3 · Los parámetros que vas a usar todo el semestre

OpciónQué hace
-dCorre en segundo plano (detached), sin secuestrar tu terminal.
-itModo interactivo con terminal: para meterte adentro.
--rmBorra el contenedor al salir. Ideal para pruebas.
--nameNombre fijo en lugar del aleatorio.
-pPublica un puerto del contenedor hacia tu máquina.
-e, -vVariables de entorno y volúmenes. Los estrenamos la próxima sesión.

Prueba -it y --rm metiéndote a un Linux ajeno:

docker run -it --rm alpine sh
# ya estás DENTRO del contenedor:
cat /etc/os-release   # Alpine Linux, no tu sistema
ps aux                # cuenta los procesos…
exit
El momento importantePID USER TIME COMMAND 1 root 0:00 sh 2 root 0:00 ps aux

Dos procesos. Tu máquina tiene cientos corriendo; el contenedor solo ve los suyos. Esa es la burbuja, y con --rm, al salir no quedó rastro.

Bonus para el stack del curso

docker run --rm -it eclipse-temurin:21 jshell te abre un Java 21 interactivo sin instalar nada. Escribe System.out.println("Hola SD") y sal con /exit. La descarga es grande; hazlo con calma en tu casa si la red del sábado no da.

Ejercicio 4 · Publicar un puerto: tu primer servicio

Por defecto el contenedor está aislado también de la red. Para alcanzar el servicio que corre adentro se publica su puerto con -p puerto-de-tu-máquina:puerto-del-contenedor:

navegador contenedor localhost:8080 ────► -p 8080:80 ────► nginx (puerto 80)
docker run -d -p 8080:80 --name miweb nginx:alpine

Abre http://localhost:8080 en tu navegador: la página de bienvenida de nginx, servida desde adentro del contenedor. Ahora intenta levantar otro en el mismo puerto, a propósito:

docker run -d -p 8080:80 --name choque nginx:alpine
El error que hay que conocerdocker: Error response from daemon: … Bind for 0.0.0.0:8080 failed: port is already allocated

Un puerto de tu máquina solo puede tener un dueño. La solución es otro puerto del lado del host: -p 8081:80. Bórralo con docker rm choque (nunca llegó a arrancar).

2Punto de control

Ves la página de nginx en localhost:8080 y entendiste el error de puerto ocupado (te lo vas a encontrar toda la vida).

Ejercicio 5 · Diagnóstico: entrar y leer registros

Cuando un servicio falla, estas dos herramientas son siempre el primer paso:

# una terminal DENTRO de un contenedor que ya corre
docker exec -it miweb sh
ls /usr/share/nginx/html      # ahí vive la página que viste
exit

# lo que el servicio ha escrito en su salida
docker logs miweb
En los logs vas a ver tu propia visita192.168.65.1 - - [29/Aug/2026:14:03:50 +0000] "GET / HTTP/1.1" 200 896 …

exec inspecciona el interior como si fuera una máquina aparte; logs te cuenta qué ha pasado. En un microservicio enfermo, empiezas por aquí.

Ejercicio 6 · Tu primera imagen

Hasta ahora corriste imágenes de otros. Ahora la tuya. En tu carpeta entregas/apellido_nombre/s02 crea dos archivos. Primero index.html, con tu nombre de verdad:

<!doctype html>
<html><head><meta charset="utf-8"><title>Mi primer contenedor</title></head>
<body style="font-family:sans-serif">
<h1>Hola, soy Tu Nombre</h1>
<p>Esta página la sirve un contenedor que yo construí.</p>
</body></html>

Y junto a él, un archivo llamado exactamente Dockerfile (sin extensión), la receta de tres líneas:

FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
EXPOSE 80

Constrúyela y córrela:

docker build -t mi-sitio .
docker images                 # aparece "mi-sitio"
docker run -d -p 9090:80 --name sitio mi-sitio

Abre http://localhost:9090: tu página, con tu nombre, servida por tu imagen. Eso que acabas de hacer (empaquetar una app en una imagen portable) es exactamente lo que haremos con cada microservicio del curso.

3Punto de control

localhost:9090 muestra tu página con tu nombre. Ya construyes imágenes: pasaste de usuario a fabricante.

Qué se sube y qué no

A tu carpeta s02 van tres archivos de texto: Dockerfile, index.html y evidencia.md. Las imágenes de Docker no se suben al repo (viven en tu máquina); las salidas van pegadas como texto, no como capturas, para que tu revisor pueda leerlas.

Limpieza

docker stop web1 web2 miweb sitio sitio2
docker rm   web1 web2 miweb sitio sitio2
docker system prune     # pregunta antes de borrar lo no usado

Si algo falla

SíntomaArreglo
Cannot connect to the Docker daemonDocker Desktop no está abierto (Win/Mac), o en Linux el motor está apagado: sudo systemctl start docker.
port is already allocatedEse puerto del host ya tiene dueño (a veces, tu propio contenedor anterior). docker ps para ver quién, o usa otro puerto.
The container name … is already in useYa existe un contenedor (aunque esté detenido) con ese nombre: docker rm nombre y reintenta.
Cambié el HTML y localhost no cambiaNo es bug, es la lección de la misión 2: la imagen congeló tu archivo. Reconstruye y recrea el contenedor.
permission denied … docker.sock (Linux)Falta el grupo: sudo usermod -aG docker $USER y reinicia sesión (está en la guía de instalación).
docker exec … bash no funcionaLas imágenes alpine no traen bash: usa sh.
